# ── 解析器测试必须装的两个 ────────────────────────────────────────────────
# 这两个曾经被划进「worker 侧重依赖，黄金样本走 HTTP 用不着」而故意不装。
# 那个判断对黄金样本成立，对**解析器测试**是错的，代价被实测量化过：
#
# B5（long_description 吸进容器外的价格/库存/评分）的回归防线共 24 个用例，
# 在没装 selectolax 的 venv 里 23 个 skip。拿五种变异去打这条防线：
#   M1 字面回退 .traverse()      -> 抓到（但只靠 AST 源码守卫抓到）
#   M4 多加一处 .traverse()      -> 抓到（同一个守卫）
#   M2 叶子节点守卫回退          -> 6 passed / 28 skipped   全绿，看不见
#   M3 词粘连回退                -> 6 passed / 28 skipped   全绿，看不见
#   M5 配送属性读取回退          -> 6 passed / 28 skipped   全绿，看不见
# 也就是说：**只有字面上重新引入 `.traverse()` 这个 token 的回归会被抓到**，
# 任何语义等价的回归都能一路绿灯发出去。
# 装上这两个，同样的命令从 6 passed/28 skipped 变成 31 passed/3 skipped、零失败。
#
# selectolax 还是**生产引擎**（requirements.txt:12，只要 import 得到就走它），
# 不装它等于解析器测试跑的根本不是生产路径。
selectolax>=0.3.21
dateparser>=1.2.0
